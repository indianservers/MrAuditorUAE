# Risk assessment and lineage

Risks support financial-statement, assertion, account-balance, transaction-class and disclosure levels. Original configurable qualitative inherent/control ratings are not presented as an ISA formula. The nine assertion codes are centrally validated. Significant/fraud flags, audit area, narrative, response, owner, due date and scoped source references are retained.

Actual Phase 2 findings, journal lines, snapshots and sampling runs can be linked. The service checks tenant, entity and financial period, and checks engagement identity for audit-record links. It rejects missing or out-of-scope sources. The Phase 2 source record remains authoritative; linking creates no duplicate anomaly.

The risk UI provides assertion selection, a dense register showing assertions and inherent risk, preparation/review actions and source selectors. Programs, procedures, testing, evidence and papers use the same validated source-reference model.

Scenario B imports a real synthetic ledger, executes analytics, links an actual resulting anomaly into a risk, requests a structured mock explanation and preserves citations. Live semantic AI evaluation remains external. The implementation does not infer fraud or causation from an indicator.
