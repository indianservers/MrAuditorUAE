# Structured financial AI suggestions

Four secured routes extend the existing Phase 1 provider interface and execution/usage audit tables: /ai/account-classification, /ai/anomaly-explanation, /ai/audit-procedures and /ai/financial-commentary. The diagnostic /ai/execute contract is preserved. Real compatible providers use the selected task's Pydantic JSON schema; deterministic mock outputs explicitly describe themselves as mock suggestions and remain pending review.

Requests identify an authorized committed snapshot, optional account/line IDs, optional matching analytics run and prior snapshot. Evidence is assembled from database facts, not arbitrary uploaded prompts. Selected lines must belong to the exact snapshot; accounts/prior snapshots must match the entity/client. Party names and free narrations are excluded from default AI context. At most ten lines and bounded comparative account context are included, and the serialized request has a 12,000-character limit.

Classification returns a proposed category/group, explanation and confidence. Anomaly explanation returns possible issues, verification steps and evidence requirements. Procedure suggestions return tests/evidence/assertions/reviewer notes. Commentary uses deterministic current/prior values and variances and explicitly cannot establish causation. All schemas require requires_review=true and references to provided UUID evidence; citations outside the supplied set are rejected. Mock classifications remain Unclassified rather than fabricating confidence.

Successful responses are deliberately stored as financial_ai_suggestions, with model execution/template metadata and pending_review status. POST /ai/suggestions/{id}/review records an authorized approve/reject decision and reviewer identity without editing journal lines. Applying an account classification requires the separate accounting.map permission and an explicit approved mapping version. Ledger facts have database immutability protection.

Provider timeouts/retries, approved models, token caps and content-free execution/usage logs come from Phase 1. A Redis tenant hourly request limit adds a bounded usage control. This release does not claim an exact monetary cost cap without a maintained provider-price catalogue; enforce provider account spending ceilings as well. AI text is advisory professional material, not an accepted finding or a replacement for deterministic computation. Full raw prompts are not retained. Structured suggestions are sensitive tenant data and need production retention/encryption/backup policies. No paid AI request was made without supplied credentials.
