# Zoho Books integration

Implemented against the official [Books API introduction](https://www.zoho.com/books/api/v3/introduction/), [OAuth specification](https://www.zoho.com/books/api/v3/oauth/), [chart-of-accounts API](https://www.zoho.com/books/api/v3/chart-of-accounts/), [journals API](https://www.zoho.com/books/api/v3/journals/) and [multi-data-center OAuth guidance](https://www.zoho.com/developer/oauth/multi-dc-support.html). Regional Books endpoints include the UAE .ae API; OAuth uses the matching accounts domain, including Canada's accounts.zohocloud.ca exception.

POST /accounting/connections with provider=zoho, approved region, authorized scope and client_id/client_secret credentials. Supply a generated CONNECTOR_ENCRYPTION_KEY first. POST /connectors/zoho/{id}/authorize with a server-allowlisted redirect_uri, complete user consent at the returned URL, then POST code/state to /callback using the authorized AuditOS identity. State is cryptographically random, hashed, expires after ten minutes and is consumed after successful exchange. This backend has no browser callback frontend. Configure the registered redirect integration to deliver the code/state to the authenticated caller.

GET /organizations lists accessible organizations; POST /organization selects an ID only after verifying actual access. POST /sync dispatches a background job by default, or background=false performs a small synchronous extraction. GET /connectors/zoho/sync-runs/{id} retrieves the scoped manifest. The worker result references the sync-run ID.

Scopes request read access to settings, accountants, invoices, bills, credit notes and contacts. The adapter paginates chartofaccounts, journals, invoices, bills, creditnotes and contacts, requests native journal details, and preserves every received page/detail before derived processing. Only published manual journals in the selected financial period are staged; original out-of-period details remain preserved and excluded counts are disclosed. excluded nonpublished counts are disclosed. Resource raw amounts parse as Decimal. The adapter uses the official debit_or_credit, amount/bcy_amount and journal-date fields. Source account IDs are stable canonical codes; the chart's displayed source code remains in raw source records.

401 can trigger one credential refresh. 429/5xx/network failures use bounded backoff. Missing permissions/organization access, revoked refresh tokens, data-center mismatch, repeated pages and incomplete pagination fail explicitly. The implementation performs full resource pagination; resource-specific incremental watermark synchronization is not yet implemented. It never invents a GL-report endpoint or treats invoice totals as double-entry GL completeness. Use a supported full GL/TB report-upload fallback and independent source controls.

Transport tests cover OAuth refresh, regional domains, rate limiting, pagination and partial failures. Optional live smoke tests require LIVE_ZOHO_SMOKE=1 plus authorized environment credentials. No live Zoho account was connected during this implementation; account-plan permissions and exact production report availability remain integration prerequisites.
