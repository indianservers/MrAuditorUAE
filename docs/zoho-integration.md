# Zoho Books integration

Implemented against the official [Books API introduction](https://www.zoho.com/books/api/v3/introduction/), [OAuth specification](https://www.zoho.com/books/api/v3/oauth/), [chart-of-accounts API](https://www.zoho.com/books/api/v3/chart-of-accounts/), [journals API](https://www.zoho.com/books/api/v3/journals/) and [multi-data-center OAuth guidance](https://www.zoho.com/developer/oauth/multi-dc-support.html). Regional Books endpoints include the UAE .ae API; OAuth uses the matching accounts domain, including Canada's accounts.zohocloud.ca exception.

POST /accounting/connections with provider=zoho, approved region, authorized scope and client_id/client_secret credentials. Supply a generated CONNECTOR_ENCRYPTION_KEY first. POST /connectors/zoho/{id}/authorize with a server-allowlisted redirect_uri, complete user consent at the returned URL, then POST code/state to /callback using the authorized AuditOS identity. State is cryptographically random, hashed, expires after ten minutes and is consumed after successful exchange. The browser callback is `/integrations/zoho/callback`; register its exact public URL with Zoho and in `ZOHO_REDIRECT_URIS`. Select an accessible organization after consent; creation cannot bypass organization verification.

GET /organizations lists accessible organizations; POST /organization selects an ID only after verifying actual access. POST /sync dispatches a background job by default, or background=false performs a small synchronous extraction. GET /connectors/zoho/sync-runs/{id} retrieves the scoped manifest. The worker result references the sync-run ID.

Scopes request read access to settings, accountants, invoices, bills, credit notes and contacts. Version 3 extracts `chartofaccounts` with `AccountType.All`, then paginates the documented `chartofaccounts/accounttransactions` endpoint for every account with `TransactionType.All` and the selected `date_start`/`date_end`. This expands GL extraction to system-generated postings rather than only manual journals. Native account IDs, transaction type/ID, categorized posting IDs, dates, debit/credit sides and amounts are retained. Missing identities, conflicting accounts, duplicate postings and invalid amounts fail extraction. Original pages are preserved before normalization. Manual journal details, invoice/bill/credit-note/contact lists remain evidence and are never added again to the ledger.

The derived imports are `zoho-general-ledger.csv` and `zoho-chart-of-accounts.csv`. Validate and explicitly activate them through the accounting workflow. Native currency/rate data must support functional-currency normalization; missing foreign-currency rates block validation. Extraction totals are grouped by currency. An absent account-feed pagination context triggers further page requests until an empty page; repeated pages, invalid continuation flags and safety-limit exhaustion fail. This behavior needs live verification for each region/plan.

401 can trigger one credential refresh. 429/5xx/network failures use bounded backoff. Missing permissions/organization access, revoked refresh tokens, data-center mismatch, repeated pages and incomplete pagination fail explicitly. The implementation performs full resource pagination; resource-specific incremental watermark synchronization is not yet implemented. It never invents a GL-report endpoint or treats invoice totals as double-entry GL completeness. Use a supported full GL/TB report-upload fallback and independent source controls.

Transport tests cover OAuth refresh, regional domains, rate limiting, pagination and partial failures. Mocked synchronization tests verify system-generated ledger extraction and that partial failures preserve evidence without staging derived batches. Optional live smoke tests require LIVE_ZOHO_SMOKE=1 plus authorized environment credentials. No live Zoho account was connected during this implementation; account-plan permissions, foreign-currency semantics and exact production report availability remain integration prerequisites.

For complete opening/movement/closing report coverage, export a detailed GL, an accrual TB with opening and closing balances, and the full chart for the same company/period, then use “Import complete report set” with source Zoho Books. Supply independent GL counts/totals where available. A trial balance is never inferred from invoice totals or the current account balance. The documented [detailed GL export](https://www.zoho.com/sa/books/kb/reports/detailed-general-ledger.html) includes opening and closing balances; flatten grouped report headings/subtotals before mapping. A report-set arithmetic match is not a live certification or proof that the source omitted nothing.

The optional `test_live_zoho_ledger_against_source_controls` test reads authorized source data without writing to Zoho. Enable `LIVE_ZOHO_LEDGER_SMOKE=1` only for the intended test organization. Configure `ZOHO_REGION`, `ZOHO_CLIENT_ID`, `ZOHO_CLIENT_SECRET`, `ZOHO_REFRESH_TOKEN`, `ZOHO_ORGANIZATION_ID`, `ACCOUNTING_PERIOD_START`, `ACCOUNTING_PERIOD_END`, `ACCOUNTING_FUNCTIONAL_CURRENCY`, and independent `ZOHO_EXPECTED_GL_ROWS`, `ZOHO_EXPECTED_GL_DEBIT`, `ZOHO_EXPECTED_GL_CREDIT` in the test process's secure environment. Run from backend: `uv run pytest tests/phase2/test_live_connectors.py -q`. The ordinary test run skips live account access. This check is a prerequisite, not a replacement for account-level TB reconciliation and reviewer sign-off.


## Recovery and optional evidence

The connection's **Sync health and recovery** panel enables document/payment detail evidence, invoice attachments and documented document deltas. Enabling details on an older grant may need renewed customer/vendor-payment read consent. Invoices, bills and credit notes have separate transactional watermarks with a five-minute overlap. The account-transaction GL continues full pagination, so a document delta is never mistaken for a complete GL or deletion feed.

Every raw page is independently committed to private storage before a checkpoint is saved. Use the saved session UUID to resume, then reconcile independent opening/GL/closing controls and review the derived import. Organization currency is verified both on selection and extraction. Source FX/base inconsistencies block staging; regional gains/losses and revaluation behavior still need live qualification. No generic undocumented TB endpoint is called.
