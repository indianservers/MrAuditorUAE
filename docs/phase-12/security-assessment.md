# Security assessment

Evidence date: 18 October 2026. Scope: local synthetic release candidate.

Primary reference: [OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS/releases/tag/v5.0.0), not older ASVS guidance. asvs-assessment.json maps chapter-level applicability and partial evidence; it is not a complete requirement-level attestation.

Executed: local Trivy configuration scan, backend pip-audit (no known dependency vulnerabilities at scan), frontend npm audit (zero reported), ML npm audit (three moderate findings), Bandit source analysis (all findings retained in sast-bandit.json), Gitleaks history and working-tree text scan with exact reviewed synthetic-value allowlists. The original unreviewed finding reports remain available. XML builders/ParseError imports were distinguished from parsing: actual untrusted XML paths use defusedxml. Analytics SQL uses validated numeric/date fields, literal quote escaping, parameter values or generated placeholders; SQL construction findings remain visible for independent review. Node invocation uses fixed executable/worker path, bounded validated configuration and no customer JS. No known high/critical exploit was confirmed by these scans; this is not proof of absence.

New controls: encrypted replay-resistant TOTP, mandatory verified platform MFA, production MFA for protected APIs, access session revocation, strict production demo/schema/role checks, separately provisioned operators, audited versioned subscription changes, per-tenant quotas and background checks. Missing/blocked: real scanner/isolated parser qualification, independent authenticated DAST/penetration testing, container-image scanning and provider-complete cloud validation, full ASVS manual review, secrets key rotation/recovery drill. Trivy IaC/Dockerfile configuration scan executed: no high/critical findings, two low findings retained for S3 access logging and RDS performance telemetry. Docker image build/scan and Terraform provider/account validation remain unavailable here. The attempted CI configuration scan detected zero supported files, so it provides no workflow-security clearance; workflows were syntax inspected separately. Do not report unavailable scans as clean.
