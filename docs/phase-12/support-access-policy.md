# Platform and support access

Evidence date: 18 October 2026. Scope: local synthetic release candidate.

A separately provisioned active PlatformOperator plus verified MFA can list operational tenant/subscription/usage metadata, readiness and release records, and perform audited subscription/lifecycle changes. A firm Platform-named role alone does not grant operator access. Operators receive no automatic tenant membership, client assignment, GL/workpaper/tax/evidence/chat access, credentials or support impersonation endpoint.

Exceptional support access is NOT_IMPLEMENTED and therefore denied by default. If required later: obtain customer/controller and professional owner authorization, named purpose/resources, least privilege, explicit expiry, independent approver, immutable access and download logs, revocation and retrospective review. Avoid creating a generic bypass route. Platform provisioning/recovery must be an approved identity-management operation with independent verification; no public self-elevation API exists. The synthetic proof operator has no tenant memberships.
