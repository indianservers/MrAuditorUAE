# OCR and vouching

Extraction uses PDFium digital text and bundled RapidOCR ONNX models on CPU for images or PDF pages without usable text. Model SHA-256 values and package versions accompany results. These are local OCR models; existing TensorFlow.js accounting ML remains in place. Raw OCR recognition scores are uncalibrated and never presented as financial accuracy probabilities.

Private original EvidenceVersion bytes remain unchanged. Extraction checks the object's hash, requires CLEAN malware status, and runs in a spawned process with a 120-second timeout. Limits: 25 MiB original, 20 pages, 20 million pixels/page and 200,000 text characters. ZIP is bounded to 20 documents/100 MiB expanded with traversal, nested-format and compression-ratio restrictions. TIFF frames are bounded. Documents in ZIP retain separate fields; a single-member extraction is required for a vouching candidate. Multi-document totals are never merged into one invoice.

Each block retains page, text, location, coordinate system and recognition score. Digital text has page-level provenance and an explicit absent box; raster OCR has actual pixel polygons. The browser requests a hash-checked raster preview, with extracted regions overlaid. Original PDFs are not executed inline. Corrections retain prior field values and provenance in immutable versions; amount/date parsing failures are rejected. Review is separate, version checked and independent of all contributors.

Vouching uses actual SamplingRun/SamplingItem IDs, population receipts, method, parameters and seed. It compares actual selected journal lines with authorized extraction results using reference, counterparty, amount, currency, date and available tax/PO/payment fields. Missing data remains missing, and ties remain ambiguous. Auditor candidate acceptance is distinct from machine matching and independent review. Missing-evidence requests and findings use the existing audit record services, with sources linked to the selected journal and result. An exception is recorded as an exception rather than a documentary match.

Supported bounds are 2,000 sampled lines and 200 extraction results/run. Samples above this bound need a partition workflow; automatically partitioned vouching is not implemented. No claim of statistically representative OCR testing, multilingual accuracy qualification, 10,000-document throughput or live malware-scanner qualification is made by the generated fixture tests.
