# Source-backed reports and client collaboration

The `/reports/statutory` designer stores versioned engagement-bound templates, 15 categories and 11 block types. Blocks support source tables, comparatives, checklists, disclosures, reconciliations, analysis, findings, narrative, references and conclusions. Native drag/drop and keyboard move controls reorder blocks. Non-narrative blocks require approved records or independently reviewed current intelligence. IFRS/tax/VAT/TP adapters require an approved release record and current exact run. Nested report sources are rejected. Source permission is checked again on reads.

Templates require independent approval before generation. Generated reports preserve source bodies, versions/hashes, firm identity and provenance. DOCX/PDF/XLSX exports are explicitly DRAFT, not signed or filed. Paper previews bound large rows/text with explicit disclosure; XLSX retains full source JSON in string cells, chunked below cell limits. There is no electronic signing or regulator submission adapter. Do not infer complete statutory wording from a report category.

Client collaboration (`/client-collaboration`, public `/client-share/{tenant}/{link}`) is disabled until the firm policy explicitly enables account-free access. Issued links have a hashed high-entropy token, secret URL fragment, <=7 day expiry, explicit retention date, request revision scope and byte/upload/response limits. Tokens are never included in list results. Public responses reveal only the linked request. Live issuer membership, permissions, assignment, policy and request state are rechecked. Revocation is immediate; editing the request invalidates an older link.

Guest identity is unverified. Original responses and staff acceptance receipts are append-only (migration 0018); accepting a response does not approve an audit conclusion. Uploads use private evidence storage and existing malware scanning; unavailable scanning quarantines files and blocks download. No email is sent automatically. Retention metadata is recorded; automated disposal and public ingress rate limiting still need operational qualification. Public browser request, submission and revocation tests pass in an isolated account-free browser context; backend capability-security tests also pass.
