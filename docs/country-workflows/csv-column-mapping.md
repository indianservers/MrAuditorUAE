# Original CSV export column mapping

Country workflows can prepare sources from retained UTF-8 CSV exports whose headings differ from the source contract. This applies to the shared and country-specific canonical table types, including bank schedules, payroll registers, tax schedules, stock populations and audit evidence schedules. It does not authenticate an ERP, bank or government export or replace a qualified native-format adapter.

In **Prepare sources**, select the CSV format and source table, then enable **Map original CSV columns**. Select comma, semicolon or tab as the separator. For each field that differs, enter its exact original column heading. Blank entries use the standard contract field name. Declare every excluded heading separately, one per line, and explain the mapping/exclusion assessment. The original document remains retained unchanged and available for download.

The mapping is explicit and case-sensitive. Arabic and other Unicode headings are preserved. Each source column can feed at most one field; unsupported fields, missing named headings, duplicate headers, competing columns for a field, mapped-and-excluded columns and unacknowledged extra columns fail preparation. Required values, field lengths, duplicate row identifiers, 5,000-row and 10 MiB bounds, nil controls and independent currency totals still apply. Even excluded cells must satisfy raw row bounds.

Values follow the existing contract: surrounding whitespace is trimmed and typed validation applies. The optional transaction-only debit/credit profile below derives one signed amount. Other mappings do not parse local date conventions, change decimal/grouping separators, convert currencies, infer registrations or invent a row identifier. Exports requiring other operations need an explicitly supported transformation or native reader. Non-CSV native imports reject CSV mapping options.

For transaction sources with separate debit/credit columns, choose **Transaction amount columns**, select debit minus credit or credit minus debit, and name both exact original headings. The sign convention is an explicit assessed input, never inferred from the country, bank name or column labels. Signed-amount mapping cannot compete with the derived amount. Neither side column may be reused for another field or excluded. Values must be unsigned plain decimals with at most twenty integer and eight fractional digits; negative values, scientific notation and grouping/decimal separators other than a decimal point fail. Both sides nonzero or both sides blank fail the whole source. One blank side means zero only if the other side contains an explicit value. Two explicit zeros are valid zero movement. No row is skipped to make the controls agree.

Each derived row retains normalized source debit/credit amounts and the chosen sign basis. The mapping receipt records the selected headings, derivation and blank-side policy; the source review screen and XLSX export expose that receipt. This does not establish account ownership or payment execution. Reconciliation still applies the existing reference, amount, date, population and balance-control requirements; converting a representation does not automatically clear an unmatched movement.

The source result displays the applied field-to-heading mapping, exclusions and assessment. Its `csv_mapping` receipt also retains the original header list, delimiter and validation basis. Independent source review preserves that receipt, and source XLSX exports include it. Rule-document binding occurs after mapping and still rejects conflicting evidence-version or hash references.

The synthetic example `sample-inputs/SYNTHETIC-mapped-bank-export.csv` uses semicolons. Map `id` to `رقم`, `account` to `Account`, `date` to `Date`, `currency` to `CCY` and `amount` to `Signed amount`; explicitly exclude `Description`. Declare one row and AED 100.25. This is a source-import example, not a verified bank statement or a complete bank reconciliation.

The additional synthetic example `sample-inputs/SYNTHETIC-split-bank-export.csv` contains two movements using `Debit` and `Credit`. With debit minus credit its independent control is AED 95.25; with credit minus debit it is AED -95.25. It retains separate references `REF-1` and `REF-2`. It is not evidence of a real account or bank payment.

`csv-mapping-unit-results.xml` records 349 targeted tests, including thirty-two focused mapping/derivation cases and existing country, payroll, benefit and native-source regressions. `csv-mapping-integration-results.xml` records ten database/API tests, including original download, retained Unicode headings, independent review, XLSX receipt, rejection of unacknowledged columns and reconciliation of a split-column source against an independent synthetic cashbook. Sixteen workflow UI tests, frontend type checking, production build, scoped lint and source-schema type checking pass. Integration scanner/broker doubles remain explicit and do not qualify production integrations.
