# CSV and XLSX supporting schedules

Supporting tables now accept retained clean CSV or macro-free XLSX evidence for bank and open-item schedules. The XLSX path reuses the ledger ingestion reader's archive, formula, macro and external-link checks instead of introducing a second permissive workbook loader. The original workbook remains private retained evidence and is never rewritten.

In Supporting tables, select the evidence and table kind. Enter the exact worksheet name for multi-sheet workbooks; a single-sheet workbook can select its only sheet automatically. The receipt identifies the selected worksheet and every unselected worksheet. This represents one worksheet population, not a declaration that the entire workbook has been reconciled.

The first row contains the existing canonical supporting-table headings. All non-empty data rows in the selected sheet are included, including hidden rows; physical row numbers are retained across blank rows. Headers must be distinct, non-empty and within the column bounds. Original XLSX header text and normalized trimmed headings are retained separately. Unrecognized headings are listed as excluded columns and require assessment against original evidence during independent review.

Numeric cells use their original worksheet XML decimal values, not a float-to-string round-trip. Text amounts use the explicitly selected decimal/grouping convention; numeric cells use their stored decimal values independently of that text convention. This preserves stored precision but cannot recover digits already rounded before the workbook was saved. Numeric inputs are bounded to the supported twenty integer/eight fractional digit profile; retain identifiers requiring leading zeros, display formatting or greater precision as text. Currency symbols, percent displays and custom number formats do not determine accounting meaning.

Typed Excel date cells use the workbook's actual date epoch, which is recorded in the receipt. Date cells with a time or timezone are rejected for these date-only schedules. Text dates still follow the explicit ISO/DMY/MDY choice. The reader does not infer locale, convert currencies or evaluate formulas.

Formula cells anywhere in the selected table, including otherwise excluded columns, fail preparation. Cached formula results are not accepted. Macros, external links, duplicate ZIP members, duplicate cell identities, spreadsheet error cells, unsupported original numeric precision and malformed workbooks fail closed. This profile does not support XLS, XLSM, ODS, encrypted workbooks, arbitrary layouts, merged multi-row headers or PDF/image table extraction.

Supporting evidence is bounded to 10 MiB. The shared XLSX reader enforces archive/decompression and compression-ratio checks, at most 100 columns and, for this profile, 20,000 physical/data rows and 200,000 original cells. Country-workflow bridges retain their tighter 5,000-row population limit. Files extending beyond those limits must be partitioned into explicitly scoped sources; no truncation is performed to make a control agree.

After independent table review, reuse it through the [bank bridge](supporting-bank-bridge.md) or [receivable/payable bridge](supporting-open-items-bridge.md). Prepared sources retain worksheet and physical-row links, table-layout receipts and original evidence hashes. The bridges still require their own account, side/date/sign assessment and independent controls. Replacing original evidence invalidates dependent versions through existing lineage checks. Worksheet import is not bank ownership verification, completed payment evidence or a professional audit conclusion.

Verification receipts: `supporting-xlsx-unit-results.xml` contains 344 targeted tests, including eleven XLSX cases and existing ledger reader, country, audit and bridge regressions. Tests exercise exact original numeric values, explicit worksheet selection, hidden/blank-row handling, numeric versus text conventions, date epochs, header provenance, formula rejection, forbidden workbook members and numeric bounds. `supporting-xlsx-integration-results.xml` contains four database/API tests across XLSX bank/open-item preparation and the existing bridges. XLSX cases verify independently reviewed worksheet reuse, original download bytes and retained worksheet metadata. Nineteen targeted UI tests, production frontend build, frontend type checking, reader-module type checks and scoped lint pass. Scanner/broker doubles remain explicit; these results do not qualify live services, representative client pilots or the full country roadmap.
