Existing accounting schedules in the reporting workbench
=======================================================

Inventory Costing & NRV and Payroll & Benefit Accounting Bridge now enable
Calculate approved inputs for their existing deterministic backend engines.
The selected assumptions are sent to the existing engagement-scoped calculate
endpoint. Backend authorization, independently approved assumptions and profile
requirements remain unchanged. Calculation does not post a journal, issue an
opinion, authenticate inventory, perform an actuarial valuation or instruct a
payment. Any journal proposal retains its separate review and posting controls.

Calculation-type choices are scoped to the engagement and workspace. Switching
subtype, workspace or engagement clears the selected assumptions, immutable
run, selected financial line and reporting profile in the calculation panel.
An instrument choice cannot become the calculation type of an inventory
workspace. Workflows without a standalone numeric engine remain disabled.

The shared accounting UI is used by UAE and India engagements; enabling an
engine does not choose an employment regime or establish a national statutory
calculation. The benefit framework and externally supplied expert figures
remain explicit approved inputs. Inventory costing still has its existing
purchased-stock and matched-transfer scope and its separate count/custody,
valuation evidence and quantity reconciliation requirements.

Seven new navigation tests cover both newly enabled routes using UAE and India
engagement identifiers, correct selected-record submission, subtype changes,
engagement changes, cross-workspace mode isolation and nonnumeric controls.
They overlap the full 515-test frontend suite. Hosted coverage also prepares
separately reviewed stock and benefit assumptions, calculates each through
the UI, checks retained values and NOT_POSTED status, and compares complete
downloaded immutable JSON. That later hosted source must pass separately;
authoring the browser case alone is not execution evidence.

Reporting profile, approved-assumption and immutable-version selectors have
independent 50-record pages and display the server's total. A selection remains
available when moving to another page; it is not replaced with that page's
first row. A newly generated run can remain selected before its list page
refreshes. Unavailable/loading pages remain explicit. Changing the active
tenant also clears the calculation controls and retained record labels.
The backend continues to enforce current permissions and approved input state
when any selected record is used. Paging itself does not approve a record.

Tests reach all 151 entries in each selector, exercise independent paging and
outside-page selection, and verify unavailable/loading states. Hosted coverage
places each selected approved stock/benefit input behind 55 newer unapproved
drafts, navigates to it, returns to the first page and calculates the retained
selection. Source-specific hosted execution is required before claiming this
later browser case has passed.

Financial statement review also pages the existing kind-filtered immutable
financial-run list. It no longer receives a mixed-kind first-page list from
the parent workbench. Creation dates accompany the run identifiers, and the
current run is omitted from comparison choices. Displayed page counts describe
the server population and explicitly include that omitted current run. An
earlier draft beyond the first 100 records remains selected when paging back;
the comparison request retains its exact ID. This changes selection access,
not the backend comparison, source-freshness or independent approval rules.

Inventory costing results present item values and separate movement, transfer
and issue populations as complete paged tables. Each table keeps every row and
the union of original fields; its page controls do not change another table.
Amounts retain their exact supplied decimal strings. The same renderer serves
group source-account lineage. Nonstructured retained rows remain explicit
alerts instead of disappearing from a complete-population claim.

Benefit obligation and payroll bridge values have separate named rollforwards.
The explicit employment framework, supplied expert figures, payment state,
zero/unknown distinctions and original calculation limitations remain visible.
Original provenance and any additional result fields remain available through
Complete retained calculation and provenance. These are read-only views over
the original immutable result. New structured-layout browser assertions and
screenshots require their own hosted execution; earlier JSON-paragraph
screenshots prove the calculation workflow, not this later presentation.
