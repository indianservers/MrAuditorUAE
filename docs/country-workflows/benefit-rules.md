# UAE benefit rules: retained evidence and independent review

The existing `uae-benefit-review` calculation now binds supplied benefit rules to actual retained evidence. It does not install or qualify a UAE legal rule pack. Rates, employment regime, alternative-scheme applicability, service exclusions, salary basis, tiers, year basis and caps still require professional assessment.

Rules and employees must name the same `regime`, `cohort` and `work_model`. Neither a shared regime nor a matching amount allows a rule for a different cohort or work model. These are explicit reviewed classifications, not nationality or pension eligibility inferred from a name, salary or passport.

The `full-time` path uses the monthly basic salary and supplied tiers. The `part-time` path requires positive `annual_contract_hours`, positive `annual_full_time_hours` and an explicitly assessed `full_time_monthly_basic_salary`. Contract hours cannot exceed the comparator. It computes the capped full-time-equivalent benefit, multiplies by contract hours divided by full-time hours, then rounds once to the currency precision. It does not divide the actual part-time salary again or infer a full-time comparator. The employee's `work_model_assessment` records the basis. Full-time records reject proration inputs to avoid silently ignoring contradictory data. Other work models and alternative schemes block this calculation pending a supported assessment.

The hours-proportion basis appears in the official [UAE private-sector benefit guidance](https://u.ae/en/information-and-services/jobs/employment-in-the-private-sector/end-of-service-benefits-for-employees-in-the-private-sector) and [MOHRE worker guidance](https://taqyeem.mohre.gov.ae/en/media-center/Awareness-and-Guidance/workers-rights.aspx?DisableResponsive=1). Indexed official guidance was available; direct retrieval of the legislative download returned HTTP 403 during this implementation. The calculation supports supplied reviewed parameters and does not certify the current operative legislation, transitional rules, cohort or salary comparator. `work_model_constant_for_service` must explicitly confirm one assessed work model and ratio across the service span. A false value blocks the calculation for segmented assessment. Changes between work models during service require a separate supported assessment; this profile assumes the declared model and ratio apply to the supplied service span.

Prepare a `benefit-rules` canonical CSV containing the published contract fields. In addition to calculation parameters, each rule requires `source_url`, `source_version`, `source_sha256`, `source_evidence_version_id` and `applicability_review`. The reference URL describes provenance; it is not fetched or treated as proof that the cited rule is applicable. The retained clean evidence version and exact stored file hash are verified separately.

The source form can select a shared retained rule document to fill blank evidence-version and hash fields. Conflicting CSV values fail rather than being overwritten. Each rule source is bounded to fifty retained rule documents and 100 MiB of original-file verification. Superseded documents, inaccessible evidence, quarantine and hash mismatches prevent preparation or calculation through the existing evidence controls.

An independent authorized reviewer must approve the rule source before it can be used in a benefit calculation. The picker offers reviewed rule versions only, and queued API jobs enforce the same requirement. Employee service/contract facts remain a separate source. Final result approval requires reviewed current inputs and an independent final reviewer through the existing workflow controls.

Results carry the selected rule ID, retained document version, hash, URL, rule version and applicability assessment. Replacing the retained rule document marks its rule source and dependent calculation stale; uploading a replacement does not silently update an old result. Prepare, review and calculate new versions.

Existing rule CSVs containing only a free-text reference must be supplemented and prepared again. Historical immutable results remain historical records; they do not gain verified provenance automatically.

Synthetic examples are in `sample-inputs/SYNTHETIC-benefit-rules-select-retained-document.csv` and `SYNTHETIC-benefit-employees.csv`. Their parameters and employee facts are fictional test inputs, not a legal recommendation. Select an actual retained test document when importing the example rule file; the evidence version and hash columns are intentionally blank.
