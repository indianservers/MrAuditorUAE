# Reuse reviewed receivable and payable schedules

Country workflows can prepare `audit-open-items` sources directly from current independently reviewed Supporting tables of kind `open-items`. This extends the [bank-table bridge](supporting-bank-bridge.md) using the same retained evidence, independent review, original row links, contributor separation and staleness controls.

Choose **Reviewed supporting open-item table** in Prepare sources. Select a reviewed current table, identify the control account, record the population/scope assessment, choose receivable or payable, declare the balance date and select the source sign convention. Enter independent row and currency controls using the resulting normal-sign amounts. All rows are retained; this is not an automatic filtering or allocation step.

The reviewed table must contain explicit `reference`, `currency`, `open_amount`, `counterparty`, `document_type`, `document_date` and `due_date` values. Document type is exactly `invoice`, `credit-note` or `debit-note`; a missing classification never becomes an assumed invoice. The existing supporting-table reader now retains optional `balance_date`, `document_type` and `segment` fields. Older prepared tables lacking these fields must be prepared and reviewed again where required; the bridge does not enrich historical immutable events silently.

The declared account must agree to every source account code where one is present. A source balance date must agree to the declared balance date. Rows without an original balance date use the explicitly declared reporting scope, with `supporting_balance_date_basis=DECLARED_SCOPE`; rows with the date retain it and use `SOURCE_FIELD`. Original document and due dates are required without fallback. The source row's segment is retained for subsequent ECL assessment.

Normal-sign balances mean non-negative invoices/debit notes and non-positive credit notes for both receivables and payables. **Use reported sign** makes no sign change. **Reverse reported sign** negates every reported open balance exactly once under the recorded assessment. The original normalized `open_amount` remains beside the resulting amount as `supporting_reported_open_amount`. Side and sign are never inferred from the country, account name or a negative number. Mixed source conventions require a separately assessed supported population.

The example `sample-inputs/SYNTHETIC-payable-supporting-table.csv` contains a credit-negative invoice of -100 and a credit note of +20. With payable side, balance date 30 June 2026 and explicit sign reversal, the normal-sign control is AED 80. The example is fictional and does not prove a supplier balance or payment.

Prepared sources can feed existing control-account, confirmation, settlement and receivables ECL workflows. Each workflow still enforces its own independent inputs and scope: a payable is not an eligible receivable ECL exposure, credit notes require allocation where the ECL engine requires it, and a matching control total does not establish extraction completeness. Loss rates and professional conclusions are not inferred by this import bridge.

Verification: `supporting-open-items-unit-results.xml` contains 341 targeted tests, including 23 bank/open-item bridge cases and ECL consumption through the existing engine for both UAE and India contexts. `supporting-open-items-integration-results.xml` contains six database/API tests across the new payable bridge, bank bridge and shared audit paths. The payable case verifies explicit sign reversal, invoice/credit-note preservation, independent source review, a matching independent control account, export and stale propagation after original replacement. Eighteen workflow UI tests, frontend production build, frontend type checking, source-schema type checking and scoped lint pass. Integration scanner/broker doubles are explicit; this does not qualify production services, legal rule packs or client pilots.
