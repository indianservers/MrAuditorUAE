Bounded original-evidence scanning

EVIDENCE_CLAMAV_TIMEOUT_SECONDS now configures one shared network deadline from 1 through 90 seconds. The default remains 20 seconds. Connection establishment is capped at 20 seconds or the shorter configured budget; sending and every reply fragment share the remaining total. The staging environment accepts an explicit override, while its default remains 20. The isolated browser CI job explicitly uses 90 seconds and a matching bounded upload request allowance. No production environment was changed or deployed.

Only the complete exact NUL-terminated stream: OK verdict cleans evidence. A complete non-clean reply is rejected. Missing, malformed, oversized or timed-out replies remain quarantined, and the file stream is rewound. No authority filename, digest or synthetic test identity bypasses scanning. No source PDF is rewritten or sanitized to obtain a passing result.

Optional internal diagnostics report bounded status/reason enums only, without file contents, scanner reply text, hostnames or exception details. Existing callers keep their original string return contract. Protocol tests cover both the original budget and longer shared deadlines, fragmentation and rejection, diagnostics privacy and configuration bounds; these are socket doubles, not a malware-engine qualification.

scripts/verify_authority_scans.py checks the exact original digests and real configured scanner verdicts for the ADGM and DMCC regulations/guidance PDFs before the browser job. It records public filenames, original SHA-256, size, elapsed seconds, verdict and bounded reason. A hash mismatch or any non-clean result fails the gate; a partial scan set cannot pass. CI uploads this report separately as authority-scan-evidence and preserves the existing browser artifact layout. The actual end-to-end uploads still require their own clean verdicts. CLI import/help and workflow/staging YAML checks pass locally; actual real-scanner timing and new ADGM UI proof await hosted CI.
