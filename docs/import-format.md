# Import formats and controls

POST /api/v1/accounting/imports as multipart: `file` plus `options` containing an ImportOptions JSON object. Required scope fields are client_id, entity_id and period_id. kind is gl, journals, tb or coa. source_system defaults to file. GL/journal required headings are account_code, journal_ref, posting_date and either debit/credit or signed amount. Account name is optional; account code remains mandatory. Optional fields include source_id, document_date, description, currency, exchange_rate, base_debit/base_credit, opening, counterparty, cost_center, department, project, tax_code, related_party, reversal_ref, manual and posting_timestamp.

Common aliases include Account Code, Ledger Code, GL Account, Account Name, Voucher Number, Journal Number, Posting Date, Transaction Date, Description, Narration, Debit, Credit, Amount, Balance, Currency, Cost Center and Reference. Multiple matching aliases are ambiguous and require an explicit mapping. `mapping` maps canonical field to actual heading. A saved profile's mapping.columns can be reused through profile_id. Profiles are client/entity scoped and append versions; other-client profiles are rejected.

CSV supports UTF-8 BOM, cp1252 and UTF-16, explicitly chosen through encoding; delimiters are comma, semicolon or tab. decimal_separator chooses dot or comma and validates thousands grouping. Parenthesized negatives are supported for signed values. signed_convention explicitly chooses debit_positive or credit_positive. Dates default to ISO; date_format supports declared alternatives. An offset is required for a supplied posting timestamp, and after-hours analytics separately requires a reliable-source assertion and business timezone/hours.

XLSX uses read-only parsing, never evaluates formulas, and requires an explicit sheet name when multiple worksheets exist. Other sheets are preserved in the original file but are not silently combined. Macro-enabled formats, embedded macros, external workbook links, dangerous archive size/ratio and corrupt files are rejected. Files default to a 64 MiB ceiling; chunk uploads default to 1 MiB. Amount precision is at most eight decimal places and 20 integer digits. Account codes, names, journal references and source IDs have explicit length limits.

Trial-balance rows support opening_balance, period debit/credit and closing_balance. If an explicit closing is supplied it must roll forward exactly. A closing-only signed balance can be supplied as amount, but it does not imply a testable opening or journal population. Chart-of-accounts rows need an account identifier and may include account name/source group. No implied transactions are created from TB/COA files.

expected_rows, expected_debit and expected_credit are independently supplied source controls. source_complete is an explicit operator assertion, not mathematical proof. Missing controls produce not_testable/insufficient_evidence. Tax codes are validated against an explicitly configured tax_codes list; unknown codes are review warnings, not invented UAE tax determinations.

Validation statuses are passed, failed, warning and not_testable. Blank IDs, impossible amounts, currency/FX errors, dates outside the selected period, duplicate source IDs and unbalanced journals block activation. Missing source references are preserved using a batch-local row identifier and flagged for review. Missing classifications remain unmapped; do not infer account type from a code prefix. Suspense/negative/control-account/reversal/manual-review tests need approved context and are delegated to analytics or reconciliation instead of being fabricated during import.

Use /accounting/uploads for resumable private upload sessions, PUT numbered chunks, GET received indices and POST complete. Repeated chunks must have the same hash; completion verifies total length and the final file SHA-256. Retrying completion returns the existing batch. The original package is preserved. There is no public file URL or financial CSV-export endpoint. The tested safe_cell helper is provided for future spreadsheet exports and must be applied to text cells before exposing generated CSVs to spreadsheet software.
