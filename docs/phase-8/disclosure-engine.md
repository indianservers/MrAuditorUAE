# Disclosure Engine

Disclosure preparation uses the approved IFRS source and current controlled matrix. Documentation uses >= thresholds, while RP/category/CP disclosure uses strict > boundaries. Dividends and non-original settlement/elimination records are excluded. CP aggregation requires an explicit reviewed connected-group key, including the relevant family/related group where applicable.

The output identifies required schedules/categories/groups and the separate substantive arm’s length requirement. Population completeness, exclusions and group aggregation are reviewed inputs. This is preparation support; no EmaraTax filing or external FTA submission exists. The CT bridge requires a current run, independently approved TP judgment, identical approved financial source and explicit reviewed adjustment. Downward amounts require FTA approval evidence. It creates an idempotent draft existing tax-adjustment record; CT review and computation remain in Phase 6.

CP disclosure distinguishes the broad transaction gate from qualifying payments and benefits provided. Receipts are not automatically treated as payments. Explicit RP overlap and payment/benefit classification are required for CP transactions. Dividends are excluded from RP threshold aggregation. Human adoption of the applicable legal sources remains mandatory.
