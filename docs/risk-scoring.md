# Explainable prioritization and sampling

Risk scores are deterministic weighted sums of distinct transaction-level indicators, capped at 100. Default weight is 10 per triggered rule; AnalyticsRequest.weights overrides individual rule weights within 0–100. Duplicate flags for the same rule do not double-count. Each risk_scores row stores supporting line, factor weights, combined score, band, ruleset version and creation time. Population-only Benford results do not become transaction fraud probabilities.

Bands are Low [0,25), Moderate [25,50), High [50,75), Critical [75,100]. These are internal workflow labels. They are not ISA categories, calibrated fraud probabilities or conclusions that a transaction is misstated. No machine learning or fabricated training data is used. Unflagged transactions implicitly have zero indicator score; the sparse risk table stores flagged transactions only.

Sampling supports random, systematic, monetary-unit, high-value, risk-targeted and full-population selection. Every sampling_runs row retains snapshot, method, parameters, random seed, algorithm version, user, time and result metadata; sampling_items stores selected line IDs and multiplicities. Input ordering is stable UUID order. The API uses a stable seeded MD5 permutation for random ordering, exact integer systematic indices and exact integer-lattice systematic PPS points for MUS. The separate pure reference implementation uses seeded reservoir/random arithmetic and records its own method; do not interchange algorithm versions when reproducing a sample.

MUS uses positive signed monetary values only; zero and negative values are separately counted, excluded and disclosed. Repeated PPS hits on one item retain a hit count, not duplicate sample rows. No positive population produces a blocking error. Large selections stream from a temporary DuckDB workspace into PostgreSQL in chunks. Targeted and high-value selections are not probability samples. An arbitrary caller-provided sample size does not imply statistical assurance or ISA compliance. Full sampling-workpaper methodology and approvals belong to a later phase.
